## In markup

```xml
<App defaultLocale="en" localeBundles="{{ en: { greeting: 'Hello, {name}!' }, de: { greeting: 'Hallo, {name}!' } }}">
  <I18n key="greeting" name="{user.name}"/>
  <Text>{App.translate('inbox', { count })} · {App.formatCurrency(total, 'EUR')}</Text>
  <I18n key="terms"><property name="link"><Link to="/terms">{$content}</Link></property></I18n>
  <Button label="Deutsch" onClick="App.setLocale('de')"/>
  <Locale locale="de-CH" groupSeparator="’"><Text>{App.formatNumber(1234567)}</Text></Locale>
</App>
```

Locale files: `src/locales/de.json` beside `Main.gui`, flat or nested (`{
"form": { "save": "…" } }` is `form.save`).

## The locale

- **Resolution** (XMLUI's order): `<App locale>`, then `App.setLocale()`
  (stored in `localStorage["gfui.locale"]`), then the stored choice, then the
  first `navigator.languages` entry with a bundle (or its language; any
  language when there are no bundles), then `<App defaultLocale>` ("en").
- **App sets `locale` and `defaultLocale` while it renders,** as it does the
  theme defaults. So the first render, and a server render, use them.
- **The server view** (the prerender and hydration) sees only the app's own
  locale (`locale`, else `defaultLocale`). After the takeover, the
  resolved locale applies and only text changes (decision C1, step 13's
  breakpoint mechanism; `components/tests/i18n.test.tsx` checks the node
  identity).
- **Loading:** `activeLocale` is the resolved locale once its messages are in
  (a loader: a locale file, a URL named by its locale); until then it stays
  on the last ready one. `setLocale` resolves when they are in, so keys never
  show.
- **Reactive:** `currentLocale()`, `lookupMessage` and the bundle version are
  signals, so bindings calling `App.translate` or a formatter run again.

## Messages

- **`App.translate(key, vars)` / `App.t`:**
  - Lookup order: the locale, its language, then the built-in `gfui.*`
    strings.
  - A missing key renders the key and is one diagnostic per locale and key.
  - An invalid pattern renders the key and is a diagnostic.
- **`intl-messageformat`** (decision A1): the whole MF1, with number and date
  skeletons.
  - Every argument and tag a message names gets a value: a missing variable
    renders as nothing; a tag without a handler renders its text.
  - XMLUI's `<link/>` is rewritten to `<link></link>` first.
- **`<I18n key="…" …vars>`:**
  - Any prop besides `key` is a variable (a leading `:` is stripped).
  - The compiler passes `key` as `$$propKey`, since React keeps `key`.
  - A `<property name="x">` with markup is a slot (`$$slot.x`, context
    variable `$content`, the tag's text) that replaces `<x/>` or
    `<x>…</x>`.
  - It renders inline content (no element of its own).
- **Bundles:**
  - `localeBundles` takes XMLUI's shapes: a locale map, `{ locale, messages
    }`, a URL or an array. A URL named by its locale (`de.json`) becomes a
    loader; another URL loads at once and needs a `"locale"` field.
  - App registers them while it renders, again only when they change
    (compared by JSON).
  - `App.registerLocaleBundles(...)` does the same from script.

## Formatters and `<Locale>`

- **On `App`:**
  - `formatNumber`, `formatCurrency` (default currency: the profile's, else
    USD), `formatDate` (XMLUI has none), `formatList`,
    `formatRelativeTime`, `compare`, `pluralRules`;
  - `isRtlLocale`, `locale`, `localeSource`, `availableLocales`,
    `direction`.
- **`<Locale>`:**
  - Its props: `locale`, `decimalSeparator`, `groupSeparator`
    (`thousandSeparator`), `minusSign`, `currency`, `numberingSystem`. The
    separators and the minus sign replace parts of `formatToParts`.
  - It provides its profile through React context (I18n, Value, Table, the
    date inputs).
  - Through `childContextVars: ["App"]`, its children's `App` is an App
    object over its profile (decision E1); `App.locale` is the scope's.
  - It renders a `display: contents` `<div lang dir>`.
  - A lazy locale suspends its children (Suspense, `use(localeLoad(...))`)
    until the messages are in; the prerender notes the load and renders
    again.
- **Limit:** a user component's own script resolves `App` to the global
  (scope isolation); its built-in children still follow the Locale through
  React context.
- **Components without their own locale follow the nearest one:**
  - `Value` and `Table` (`typeOptions.locale` still wins), and the Table's
    sort collation;
  - DateInput, DatePicker and TimeInput (their `locale` prop wins).

## Framework strings (decision D1)

- **`gfui.*` keys** (`BUILT_IN_MESSAGES`):
  - Form's buttons and its warnings dialog;
  - the validation messages (`runtime/src/forms/rules.ts`);
  - the dialogs' Close/Cancel and unsaved-changes texts;
  - FileInput's Browse and the drop zone's text;
  - step 33's error panel;
  - the `aria-label`s.
- **Components** read them with `useFrameworkText()`, in the nearest locale,
  re-rendering when a bundle is added. A prop that sets the text (`saveLabel`,
  `buttonLabel`, …) still wins.

## Direction

- **`<App direction="auto|ltr|rtl">`:** `auto` uses `Intl.Locale`'s text
  info: `getTextInfo()` in browsers, `textInfo` in Node, else a CLDR list.
- **Where it goes:** `dir` on `.gfui-App` (rendered, so prerendered) and in
  Mantine's `DirectionContext`; `dir` and `lang` on `<html>` (the prerender
  through `injectDocumentAttributes`, then effects).
- **The App doesn't re-render for a new locale name.** It renders from the
  direction (`useComputed`, unchanged for `en` → `en-US`). It sets `lang` on
  its root and on `<html>` from a signal watch. A re-render after a takeover
  would reach Suspense boundaries that are still dehydrated (Markdown's lazy
  renderer), and React would drop their prerendered HTML (`e2e/ssg.spec.ts`
  found it). Components that show framework strings re-render on
  `messagesSignature(locale)`: which bundles the messages come from, not the
  locale's name.
- **The stylesheet** uses logical properties. `components/tests/rtl-css.test.ts`
  fails on a physical one that isn't in its list of reasons.
  `[dir="rtl"]` rules mirror the drawer's slide and the ToneSwitch.
- **In script:**
  - the Splitter measures a horizontal drag from the right edge in RTL and
    mirrors the arrow keys;
  - the Table's column resize mirrors its delta;
  - pinned columns use `insetInlineStart`/`End`, so `pinTo="left"` sticks to
    the start side.

## Diagnostics

- **E041** (an error): a message of a literal App `localeBundles` that isn't
  valid ICU, at its string literal. The plugin fails the build on a locale
  file that isn't valid JSON or ICU.
- **At runtime** these are developer diagnostics (`reportDiagnostic`), never
  the error pipeline: a missing key, an invalid locale, a bundle that fails to
  load, an ICU error in a runtime bundle.

## Divergences from XMLUI

| XMLUI | Here |
|-------|------|
| A hand-rolled ICU subset (no quoting, `offset`, `selectordinal`, skeletons; a nested plural's `#` wrong) | `intl-messageformat` |
| `<App locale>` and the bundles applied after the first render; nothing waits for a bundle | Applied while App renders; `setLocale` waits for the messages; the prerender renders the app's locale |
| `dir` only on `<html>`, in an effect | On the App root (prerendered) and on `<html>` |
| RTL by a regex of five languages | `Intl.Locale` text info |
| `App.locale` inside `<Locale>` is the root's | The scope's |
| `xmlui.*` keys; Form buttons and nine validators | `gfui.*` keys; every framework string |
| `strictI18n` | E041 and the plugin's checks at build time; runtime problems are diagnostics |
| No `formatDate` | `App.formatDate` |
| No locale files | `src/locales/*.json`, lazy except the app's own locale |
